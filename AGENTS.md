# AGENTS.md

Guidance for AI agents (and humans) working in this repo. See [README.md](README.md) for a
user-facing overview of the config.

## What this is

A personal Neovim configuration written in Lua, plugin-managed via
[lazy.nvim](https://github.com/folke/lazy.nvim). It is not LazyVim — LazyVim was removed;
the plugin set is intentionally small and hand-picked.

## Layout

```
init.lua                  -- entry point: leader keys, requires config modules
lua/config/options.lua    -- vim.opt settings
lua/config/keymap.lua     -- keymaps, diagnostic float config
lua/config/lazy.lua       -- bootstraps lazy.nvim, points it at lua/plugins/
lua/plugins/*.lua         -- one lazy.nvim plugin spec per file
lazy-lock.json            -- pinned plugin commits, written by lazy.nvim itself
```

Each file under `lua/plugins/` returns a single lazy.nvim spec table (or an array of them).
Follow that one-file-per-plugin convention when adding new plugins.

## Editing conventions

- Indentation is inconsistent across existing files (some use tabs, some spaces) — match
  whatever the file you're editing already uses rather than reformatting the whole file.
- Don't hand-edit `lazy-lock.json`; it's regenerated by lazy.nvim (`:Lazy sync`/`:Lazy update`).
- Keep plugin config declarative in the `opts` table where the plugin supports it, and use
  `config = function() ... end` only when imperative setup (e.g. `vim.lsp.config`,
  `vim.lsp.enable`) is actually required, as in `lua/plugins/lspconfig.lua`.

## LSP setup (`lua/plugins/lspconfig.lua`)

- Uses the native `vim.lsp.config()` / `vim.lsp.enable()` API (Neovim >= 0.11), not
  `nvim-lspconfig`'s old `require("lspconfig").<server>.setup{}` pattern.
- `vim.lsp.config("*", ...)` sets capabilities (from `blink.cmp`) shared by all servers.
- Some servers are configured to detect project type dynamically (via `root_dir`/`cmd`
  functions) so that a specialized toolchain plugin only kicks in for the project type it
  targets, with a generic fallback otherwise. When touching one of these, keep both branches
  working — don't collapse it back to always using the specialized config.

## Verifying changes

There's no test suite. To verify a config change actually works, don't just check Lua
syntax — drive a real headless Neovim session against a throwaway project, e.g.:

```sh
mkdir -p /tmp/scratch-c && cd /tmp/scratch-c && printf 'int main(void){return 0;}\n' > main.c
nvim --headless -u ~/.config/nvim/init.lua main.c \
  -c "lua vim.defer_fn(function()
        for _,c in ipairs(vim.lsp.get_clients({bufnr=0})) do
          print(c.name, c.config.root_dir)
        end
        vim.cmd('quit')
      end, 3000)"
```

For clangd specifically, also check `ps aux | grep clangd` to confirm which binary/flags
actually got spawned (useful since `cmd` can be a function and won't print as a plain
argv list).
